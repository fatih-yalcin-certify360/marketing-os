# Brand Portal integration

The API and worker use this integration through `BrandService.approved` and
`requireApproved`. A label manager links a local label to a Portal slug under
**Merk & bronnen → Brand Portal**. Server configuration:
`BRAND_PORTAL_BASE_URL`, `BRAND_PORTAL_API_KEY`, and shared `STORAGE_ROOT`.
Credentials and signed URLs are never sent to the browser.

Only published `production` bundles are accepted. As explicitly requested,
these become approved local brand versions immediately, without a second local
brand approval. Content approvals still apply. Local manual editing/approval is
blocked for linked brands; rules are changed in Portal.

On use, the release is checked at most once every five minutes after a successful
check; **Nu synchroniseren** forces a check. Unchanged semantic fingerprints
reuse the existing version and asset files. Changed releases create a new local
version, archive the previous active profile, and flag draft/approved content
for re-review, all in one transaction. Older release numbers are not silently
restored. Profiles retain release, slug, import time, fingerprint and local font
and logo references. Existing content remains linked to its original version;
a content revision uses the currently active brand.

The client cache is scoped by organization, configured origin, API credential
hash, slug and include/channel arguments. Signed assets are downloaded only
from the configured origin's `/v1/assets/{id}/raw` paths, with no redirects.
They are stored by content hash and read with label and hash checks. Authentication,
malformed bundle and asset failures stop use; network outages can use the prior
validated release for at most 24 hours with a visible warning. There is no
fallback when linking a new brand or when that window has expired.

## Mapping and rendering

`mapping.ts` maps semantic palette/UI tokens to the existing render contract:
primary/accent/ink, default surface, light text, heading and body families.
It selects the default RGB diapositive PNG logo for the primary-colored layouts.
Normal font weights used by the layouts are loaded from Portal. OTF is preferred,
with TTF alternatives; internal SFNT family metadata must match the declared
family before acceptance. This matters for the CS release: its Euclid TTF family
metadata is malformed, while its original OTF is usable. Canonical font family
names are supplied to resvg. System font fallback is disabled for imported brands.
The original logo is embedded by the deterministic renderer, never generated by AI.

The full content profile (style guide, content instructions, image instructions,
and examples) is passed to the prompt in tagged context. It cannot override the
system's confirmed-facts and output rules. Empty profiles stay empty and carry a
visible warning. No rules are borrowed from another brand. Extra Portal UI tokens
outside the current image-layout contract are not automatically implemented.

## Endpoints

- `POST /api/v1/labels/:labelId/brand/portal/sync` with `{ "slug": "cs-opleidingen" }`
  links and imports; `{}` refreshes an existing link. Requires `brand:write`.
- `GET /api/v1/labels/:labelId/brand` includes release and synchronization status.
- `GET /api/v1/labels/:labelId/brand/preview.png` renders an authorized brand preview.

Migration `0009_brand_portal` adds link/status fields and version provenance.
Tests: `brand-portal-client.test.ts`, `brand-portal-cache.test.ts`,
`brand-portal-sync.test.ts`. They cover isolation, errors, cache boundaries,
idempotency, immutable versions, font metadata and prompt context.

Live verification (2026-09-10): local CS Opleidingen is linked to `cs-opleidingen`,
release `0.4.0`; original logo and seven font files are local. A rendered preview
uses Behind The Nineties headings and Euclid Square body text. The release has
no content profile; the UI reports that explicitly. Existing course facts were
not confirmed and no content was published as part of this integration.
